令牌怎么拿

线上管理的「第二道门」是 GitHub 令牌——权限边界在它，不在访问口令。本页是项目文档 docs/DEPLOY.md「线上管理怎么用」的线上镜像，完整文档见项目仓库。

访问口令只防误触，不是安全边界。页面源码公开，看源码就能跳过它；真正的权限边界是你的 GitHub 令牌。令牌只存在当前标签页的 sessionStorage 里（关掉即失效），不会写进任何文件、不会发往本站之外的服务器。

1打开 GitHub 令牌设置页

登录 GitHub → Settings → Developer settings → Fine-grained tokens（直接打开：github.com/settings/tokens/new）。

2只授权本仓库

Repository access 选 Only select repositories → 选中 tm-promptforge。不要选 All repositories——单仓库是本方案的安全底线。

3只给 Contents 读写

Permissions → Repository permissions：Contents 设为 Read and write，其余全部保持 No access。不需要 Pages / Administration / Actions 等任何其他权限。

4设个短期限

Expiration 建议 30~90 天。到期即失效、需重新建——这是刻意的，不是麻烦。

5生成并复制

点 Generate token，复制那串令牌（只显示一次）。回到管理面板第二道门粘贴进去即可。保存即自动提交到仓库 gh-pages 分支，Pages 自动重建。

为什么要每人自己的令牌，不要共用

  • 归因：共用令牌会让所有提交都长一样，毁掉「谁改的」追溯；每人自己的令牌，commit 作者清清楚楚。
  • 泄露半径：共用=一人泄露全员中招；自己的令牌泄露只影响你自己，删掉重建即可。

令牌怎么吊销

GitHub → Settings → Developer settings → Fine-grained tokens → 找到对应令牌 → Delete。立即生效，无需在本站做任何操作。

常见报错

  • 401 / 403：令牌无效或权限不足——检查是否给了 Contents R/W 且限定本仓库。
  • 404：仓库或分支不存在。
  • 409：别人刚改过同一文件——面板会自动重取重试一次；仍失败请刷新页面再来。
  • 422：GitHub 拒绝了请求，面板会原样显示它的原因。
